## 현행 대체 관계 — 2026-09-15

**이 문서는 초기 설계 기록이다.** 업무·일정·문서·질문 4개 메뉴, 문서 페이지 탐색과 상세 폭 조절, 문장별 근거 확인으로 구현했다. 전 문서 LLM 요약 대신 임베딩·규칙 분석과 요청 시 요약을 사용한다. 그래프·복사 정리·DOCX/PDF 출력은 후속이다.

현재 제품명은 **눈치코치(NunchiCoach)**다. 생성·검색 모델은 설정에서 프로젝트별로 선택한다. 기본 모델 설치 PC의 별도 검사 36개와 합성 문서 77개 배포 점검을 통과했지만 실제 HWP·기관 자료·8GB 장비 평가는 남아 있다.

## 1. 시스템의 목표

이 시스템이 해결해야 하는 핵심 질문은 다음과 같다.

> “전임자의 PC를 받았는데, 어디서부터 봐야 하지?”

시스템은 전임자의 PC, 공유 폴더, USB, 백업 디스크 등에 흩어진 수천~수만 개의 파일을 자동 조사하여 다음 결과를 제공해야 한다.

```text
전임자 자료 12,438건을 분석했습니다.

주요 업무는 7개로 추정됩니다.
① 월간 실적보고
② 계약 및 용역관리
③ 감사 대응
④ 예산 및 지출
⑤ 통계자료 작성
⑥ 민원 대응
⑦ 내부 회의자료

최근 3년간 반복적으로 작성된 핵심 문서 48건을 발견했습니다.
업무 이해를 위해 아래 12개 문서를 먼저 읽는 것을 권장합니다.
```

최종 목표는 파일 정리를 넘어 다음 담당자가 **업무의 구조, 일정, 핵심 문서와 과거 처리 방식을 빠르게 이해하도록 돕는 것**이다.

## 2. 핵심 설계 원칙

AI가 모든 처리를 담당하도록 해서는 안 된다. 결정적이고 반복 가능한 처리는 일반 프로그램이 맡고, 의미 판단이 필요한 작업만 LLM에 맡긴다.

| 일반 프로그램이 담당할 일 | 로컬 LLM이 담당할 일 |
|---|---|
| 파일명·경로 읽기 | 문서의 업무 분야 판단 |
| 생성일·수정일·크기 확인 | 제목 정규화 및 요약 |
| 폴더 구조 분석 | 중요도 판단 |
| SHA-256 해시 계산 | 유사 문서의 의미상 분류 |
| 완전 중복 확인 | 연도별 업무 흐름 추론 |
| 문서 본문·표 추출 | 문서 간 관계 추론 |
| 확장자·날짜 분류 | 인수인계 설명과 보고서 생성 |
| 파일 복사·내보내기 | 자연어 질의응답 |

권장 처리 흐름은 다음과 같다.

```text
File Scanner / Parser
        ↓
구조화 및 정규화
        ↓
Local LLM 판단
        ↓
DB 저장 및 사용자 검토
```

이 구조는 속도와 재현성을 높이고 AI 오판을 줄인다.

## 4. 원본 보존 모드

공공기관 업무 자료를 다루는 프로그램에서는 원본 보존이 최우선이다. 기본 설정에서 프로그램은 원본을 수정·이동·삭제하지 않아야 한다.

```text
분석 대상 원본
D:\전임자PC\업무자료\

색인 결과
Document ID : 0001832
원본 경로   : D:\전임자PC\업무자료\통계\2024년\수질통계최종진짜최종.xlsx
업무 분류   : 수질통계
문서 유형   : 실적보고
기준 연도   : 2024
중요도      : 높음
대표 문서   : Yes
```

사용자가 명시적으로 **“정리된 폴더 만들기”**를 실행할 때만 별도 위치에 복사본을 생성한다. 이동보다 복사를 기본값으로 하고, 변경 전 미리보기와 작업 로그를 제공한다.

## 5. 파일 조사 및 메타데이터 수집

사용자는 처음 실행할 때 분석 위치를 선택한다.

```text
분석 대상

☑ C:\Users\전임자\Desktop
☑ D:\업무자료
☑ E:\백업자료
☐ 네트워크 공유 폴더
```

**자료 조사 시작**을 누르면 AI 호출 전에 다음 메타데이터를 수집한다.

| 항목 | 예시 |
|---|---|
| 파일명 | `2024년_업무보고_최종.hwp` |
| 경로 | `D:\업무보고\2024` |
| 확장자 | HWP |
| 크기 | 2.4 MB |
| 생성일 | 2024-03-02 |
| 수정일 | 2024-03-08 |
| 작성자 | 홍길동 |
| 해시 | `a819...` |
| 폴더 깊이 | 3 |

이 단계는 빠르고 재현 가능한 일반 프로그램 로직으로 처리한다.

## 6. 중복 파일과 버전 탐지

실제 업무 PC에는 다음과 같은 파일이 흔하다.

```text
보고서.hwp
보고서_수정.hwp
보고서_최종.hwp
보고서_최종2.hwp
보고서_최종진짜.hwp
보고서_최종(부장수정).hwp
보고서_최종_송부.hwp
```

탐지는 세 단계로 수행한다.

1. **해시 비교:** 내용이 완전히 같으면 완전 중복으로 판정한다.
2. **파일명 유사도:** 이름과 날짜 패턴이 비슷한 파일을 후보군으로 묶는다.
3. **본문 유사도:** 본문이 매우 유사하면 동일 문서의 버전일 가능성이 있다고 표시한다.

```text
2025 업무계획
 ├─ 2025업무계획.hwp
 ├─ 2025업무계획_수정.hwp
 ├─ 2025업무계획_최종.hwp
 └─ ★ 2025업무계획_송부.hwp
```

시스템은 최종본을 추정하되 자동 삭제하지 않으며, 사용자가 근거와 버전 관계를 확인할 수 있게 한다.

## 7. AI 문서 분석

추출한 본문을 로컬 LLM에 전달하되, 문서를 무조건 통째로 넣지 않는다. 긴 문서는 분할·요약한 뒤 문서 단위 결과를 생성하고, 응답 형식은 JSON으로 강제한다.

```json
{
  "document_title": "2025년 상수도 주요업무계획",
  "document_type": "업무계획",
  "business_area": "업무계획",
  "year": 2025,
  "importance": 5,
  "keywords": ["상수도", "업무계획", "경영", "예산"],
  "summary": "2025년도 주요 사업과 추진계획을 정리한 문서",
  "likely_final_version": true,
  "confidence": 0.92
}
```

결과는 SQLite에 저장하여 변경이 없는 문서를 매번 다시 분석하지 않도록 한다.

## 8. 업무 중심 분류

연도나 확장자 중심의 기존 폴더 구조는 인수인계에 충분하지 않다.

```text
기존 구조
업무자료
├─ 2022
├─ 2023
├─ 2024
├─ 기타
├─ 참고
└─ 예전
```

이를 업무 의미 중심으로 재구성한다.

```text
업무
├─ 예산
│  ├─ 예산편성
│  ├─ 예산요구
│  └─ 집행관리
├─ 의회
│  ├─ 행정사무감사
│  ├─ 업무보고
│  └─ 요구자료
├─ 계약
├─ 통계
└─ 내부보고
```

각 업무 안에서는 연도순으로 문서를 보여준다. 이로써 사용자는 파일 형식이 아니라 실제 담당 업무를 기준으로 자료를 탐색할 수 있다.

---

## 9. 업무 자동 발견

문서별 분류 결과를 집계하고 다시 분석하여 전임자가 실제 수행한 업무 범주를 자동 발견한다.

```text
전체 문서 8,321개 분석 결과

수질통계       1,023건
예산관리         827건
행정사무감사      582건
사업계획          419건
국정감사          206건
민원             391건
회의자료          933건
기타           3,940건
```

새 담당자는 업무 분장표에 드러나지 않는 실제 업무 비중과 자료 분포까지 한눈에 파악할 수 있다.

---

## 10. 업무 타임라인

특정 업무를 선택하면 연도별 수행 흔적을 시간순으로 표시한다.

```text
행정사무감사

2022  9월 요구자료 → 10월 제출자료 → 11월 결과보고
2023  9월 요구자료 → 10월 제출자료 → 11월 결과보고
2024  9월 요구자료 → 10월 제출자료 → 11월 결과보고
```

AI는 자료의 반복 패턴을 근거로 다음과 같이 설명할 수 있다.

> 행정사무감사 관련 업무는 매년 9~11월 반복되는 것으로 보입니다.

이 기능이 단순 파일 관리 프로그램과 업무 인수인계 시스템을 구분한다.

---

## 11. 반복 업무와 업무 캘린더

타임라인에서 반복 주기와 시기를 발견하여 업무 캘린더를 자동 생성한다.

```text
매월       월간 실적보고
매년 1~2월 전년도 실적보고
매년 3월   예산 요구자료
매년 9~11월 행정사무감사
매년 12월  다음 연도 업무계획
```

사용자는 각 일정에서 대표 문서와 전년도 처리 절차로 이동할 수 있어야 한다.

## 12. 핵심 문서 추천

수천 개 문서 중 신규 담당자가 먼저 읽어야 할 문서를 추천한다.

```text
★★★★★  2025 주요업무계획.hwp
★★★★★  2024 업무 인수인계서.hwp
★★★★★  2025 예산현황.xlsx
★★★★☆  2024 행정사무감사 제출자료.hwp
★★★★☆  주요사업 추진현황.pptx
```

추천 점수는 다음 요소를 조합한다.

```text
문서 중요도 =
최근성
+ 반복 사용도
+ 다른 문서와의 연결도
+ 문서 유형 가중치
+ 버전·최종본 가능성
+ AI 중요도 판단
```

LLM의 단일 판단이 아니라 규칙 기반 점수와 의미 분석을 결합한다.

---

## 13. 일반 검색과 AI 검색

### 일반 검색

파일명, 경로, 작성자, 본문에 대한 정확한 키워드 검색을 제공한다.

```text
2024 수질통계
```

### AI 검색

자연어 질문으로 관련 문서를 찾고 요약 답변을 생성한다.

```text
작년에 의회에서 수질 관련해서 어떤 자료를 요구했어?
```

```text
2025년 행정사무감사 요구자료 중 수질 관련 자료가 6건 발견되었습니다.
주요 내용은 원수 수질, 정수장별 검사결과, 수질민원 현황입니다.

근거 문서
📄 2025행감_요구자료_최종.hwp
📄 정수장별수질현황.xlsx
📄 수질민원현황.xlsx
```

모든 AI 답변에는 클릭 가능한 근거 문서와 관련 구절 또는 표 위치를 표시한다. 이것이 검색 증강 생성(RAG)의 핵심이다.

## 14. 문서 관계망

업무계획, 예산, 실적, 회의자료처럼 서로 연결된 문서를 관계망으로 표현한다.

```text
             업무계획
                │
       ┌────────┴────────┐
       │                 │
     예산               실적
       │                 │
    예산서.xlsx      실적보고.hwp
       │                 │
       └──── 사업 A ─────┘
```

사용자는 “이 문서와 관련된 다른 문서는?”이라는 질문으로 선행·후속·참고 문서를 탐색할 수 있다.

## 15. 폴더 자동 정리

분석이 완료된 뒤 사용자가 원하는 경우에만 정리 결과 폴더를 생성한다.

```text
AI_정리결과
├─ 01_업무계획
│  ├─ 2023
│  ├─ 2024
│  └─ 2025
├─ 02_예산
├─ 03_계약
├─ 04_의회
├─ 05_감사
└─ 99_기타
```

기본 동작은 **이동이 아닌 복사**이며, 예상 결과와 필요 용량을 먼저 보여준다.

## 16. 파일명 자동 정규화

AI는 문서 내용과 메타데이터를 바탕으로 의미 있는 파일명을 제안한다.

```text
기존: 최종진짜마지막_부장수정.hwp
제안: 2025_행정사무감사_수질분야_제출자료.hwp
```

파일명은 자동 변경하지 않고 **기존 파일명 → 추천 파일명 → 사용자 적용** 절차를 따른다. 충돌 방지와 변경 이력도 제공한다.

## 22. LLM 처리 구조

모든 파일을 한 번에 LLM에 입력하지 않고 계층적으로 처리한다.

```text
문서
 ↓
본문·표 추출
 ↓
Chunk 분할
 ↓
Chunk 요약
 ↓
문서 요약
 ↓
업무 분류
 ↓
Embedding 생성
 ↓
DB 저장
```

전체 업무 분석은 다음과 같이 진행한다.

```text
문서 요약 수천~수만 개
          ↓
업무별 Cluster
          ↓
업무별 대표 문서
          ↓
업무 요약·타임라인·반복 주기
```

## 23. 프롬프트 관리

프롬프트는 코드에 흩어두지 않고 버전이 있는 시스템 자산으로 관리한다.

```text
당신은 대한민국 공공기관 업무 문서 분석 AI다.

다음 문서의 내용을 분석하고 아래 항목을 JSON으로 출력하라.

- document_title
- business_category
- document_type
- year
- summary
- keywords
- importance
- confidence

importance는 1~5 사이 정수로 평가한다.
근거가 부족한 항목은 추측하지 말고 "unknown"을 사용한다.
```

JSON Schema 검증, 재시도 규칙, 모델·프롬프트 버전 기록을 함께 둔다.

## 24. 임베딩 모델 분리

## 27. HWP·HWPX 처리 전략

공공기관 문서에서 HWP, HWPX, PDF, Excel의 비중이 높을 가능성이 크다. 특히 HWP는 버전과 내부 구조에 따라 추출 품질이 달라질 수 있으므로 UI보다 먼저 검증해야 한다.

```text
HWP  100개
HWPX 100개
PDF  100개
XLSX 100개
```

대표 표본으로 테스트 세트를 만들고 다음 항목을 측정한다.

- 본문 누락률
- 표 구조 보존율
- 암호화·손상 문서 처리
- 첨부 객체와 이미지 인식
- 한글·숫자·날짜 추출 정확도
- 처리 시간과 실패 사유 분류

문서 파싱 정확도가 확보되지 않으면 AI 성능과 관계없이 제품 가치가 낮아진다.

## 28. 분석 상태와 재개 처리

수천~수만 개 문서 분석에는 시간이 걸리므로 파이프라인 상태를 단계별로 보여준다.

```text
전체       12,482
Metadata   12,482 완료
본문 추출   11,901 완료
AI 분석      8,420 완료
오류            62
분석 불가       519
```

프로그램을 종료해도 다음 실행 시 중단 지점부터 이어서 처리해야 한다. 실패한 작업은 원인과 재시도 가능 여부를 표시한다.

## 29. AI 확신도

AI 결과를 사실처럼 단정하지 않고 확신도를 함께 표시한다.

```text
업무 분류: 행정사무감사
AI 확신도: 92%
```

```text
업무 분류 후보: 계약 / 예산
AI 확신도: 51%
[사용자 확인 필요]
```

확신도가 낮거나 여러 범주가 경합하면 검토 목록으로 보내고, 판단 근거가 된 문장과 경로 정보를 함께 제공한다.

## 30. 사용자 교정과 분류 개선

사용자가 AI 분류를 교정하면 그 결과를 저장한다.

```text
AI 분류: 수질검사결과.xlsx → 통계
사용자 교정:                → 수질관리
```

이후 유사 문서 분석 시 과거 교정 사례를 예시로 제공한다. 별도의 모델 미세조정 없이도 사용자 피드백 기반 Few-shot 분류를 구현할 수 있다.

## 31. 폴더 설명 기능

`참고`, `기타`, `임시`, `백업`, `옛날`처럼 의미가 불분명한 폴더에 **AI에게 이 폴더 설명시키기** 기능을 제공한다.

> 이 폴더에는 2022~2024년 행정사무감사 관련 자료 184건이 있습니다. 요구자료, 제출자료, 의원질의 답변자료가 주요 내용입니다. `2024행감_최종.hwp`가 대표 문서로 판단됩니다.

폴더 설명에는 주요 업무, 기간, 파일 유형, 대표 문서, 중복 비율과 분석 불가 파일을 포함한다.

## 32. 지난해 업무 재현 기능

시스템은 같은 업무의 과거 문서를 찾아 처리 흐름을 재구성한다.

각 단계에 근거 문서를 연결해야 하며, 자료에서 확인되지 않는 내용은 추정이라고 명시한다.

## 33. 보안 설계

공공업무용 시스템은 처음부터 Local-first 구조로 설계한다.

```text
Internet Access = OFF
Cloud API       = 사용 안 함
LLM Endpoint    = 127.0.0.1:11434
Document DB     = Local
Vector DB       = Local
```

핵심 정책은 다음과 같다.

- 문서와 추출 본문을 외부 서버로 전송하지 않는다.
- 네트워크 접근은 기본 차단하고 필요한 경우 관리자 정책으로만 허용한다.
- 저장 데이터와 내보내기 파일의 접근 권한을 통제한다.
- 민감정보·개인정보 후보를 표시하고 인덱싱 제외 규칙을 제공한다.
- 모델 파일과 애플리케이션 업데이트는 검증된 오프라인 배포 절차를 지원한다.
- 실제 기관 도입 전 보안성 검토와 내부 지침 적합성 확인을 거친다.

## 37. 최종 사용자 경험

새로운 보직으로 이동한 담당자가 전임자 자료를 준비하고 프로그램을 실행한다.

```text
D:\전임자업무
[분석 시작]

파일 18,237개 발견
중복 2,103개
분석 대상 문서 14,820개
```

분석이 진행되면 다음 결과를 제공한다.

```text
당신이 인수받은 업무는 약 9개로 추정됩니다.
먼저 읽어야 할 문서 15개를 추천합니다.
```

사용자는 자연어로 질문한다.

> **사용자:** 이 업무에서 매달 해야 하는 일이 뭐야?  
> **AI:** 자료를 분석한 결과 매월 5~10일경 실적 취합 업무가 반복됩니다.

> **사용자:** 작년 9월에는 무슨 일을 많이 했어?  
> **AI:** 행정사무감사 관련 자료 작성이 집중되어 있습니다.

> **사용자:** 작년 감사자료 보여줘.  
> **AI:** 관련 파일과 핵심 내용을 근거 문서와 함께 표시합니다.

이 수준에 도달하면 전임자에게 파일 위치와 과거 처리 방식을 반복해서 물어보던 부담을 상당 부분 줄일 수 있다.

## 38. 최우선 성공 요인

### 1) 문서 파싱 정확도

AI가 뛰어나도 HWP, Excel, PDF 내용을 제대로 읽지 못하면 쓸모가 없다. 따라서 파싱 성공률과 표 보존 품질을 가장 먼저 검증한다.

### 2) 업무 의미 중심 분류

PDF/HWP/Excel 같은 파일 형식별 정리만으로는 기존 파일 관리 프로그램과 차별화되지 않는다. 의회, 예산, 계약, 감사, 통계처럼 **업무 의미 중심**으로 정리해야 한다.

### 3) 근거 문서가 있는 AI

AI가 “작년에 이 일을 이렇게 했습니다”라고 답하면 반드시 근거 문서를 클릭해 확인할 수 있어야 한다. 행정업무에서는 답변의 검증 가능성이 특히 중요하다.

## 39. 제품 정의와 다음 단계

제품의 핵심 정의는 다음과 같다.

> **전임자의 파일을 정리해 주는 프로그램이 아니라, 전임자의 업무 흔적을 분석하여 다음 담당자가 업무를 빠르게 이해하도록 만드는 Local AI 기반 업무 인수인계 시스템.**

`Ollama + 로컬 LLM`은 보안상 외부 반출이 곤란한 행정 문서를 PC 내부에서 처리하는 구조에 적합한 선택지다. 다만 실제 도입 전에는 한국어 행정 문서 분류·요약 정확도, 처리 속도, 메모리·GPU 요구량, 라이선스, 기관 보안 기준을 별도 테스트 문서군으로 검증해야 한다.

다음 상세 설계는 아래 순서로 진행하는 것이 좋다.

1. 화면별 상세 UI·UX 설계
2. 실제 DB 테이블 및 인덱스 설계
3. 프로그램 폴더·모듈·클래스 구조
4. Ollama 프롬프트 및 RAG 구조
5. Python·PySide6 기반 MVP 구현 명세
6. HWP·HWPX·PDF·XLSX 파싱 벤치마크
7. 보안성·정확성·사용성 검증 계획

이 시스템의 가치는 파일을 예쁘게 분류하는 데 있지 않다. 전임자의 문서에서 **담당 업무, 연간 일정, 반복 절차, 핵심 자료와 과거 의사결정의 근거**를 찾아 다음 담당자가 즉시 활용할 수 있는 지식으로 바꾸는 데 있다.
