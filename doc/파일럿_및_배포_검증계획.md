# 파일럿 및 배포 검증 계획

## 자동 검증으로 확인하는 범위

1. 잠금 파일의 실행 환경에서 합성 표본을 생성한다.
2. 전체 pytest와 UI/UX·자료 갱신·취소·로그 개인정보 회귀 테스트를 실행한다.
3. 밝은/어두운 테마, 큰 글자, 검색 결과 없음과 마지막 페이지를 렌더링한다.
4. PyInstaller 실행 파일을 새 경로에 빌드한다.
5. 실행 파일의 selftest로 로고·SQL·프롬프트 포함 여부와 표본 본문 추출을 확인한다. 필수 파일이 없거나 파싱 실패가 있으면 실패 코드로 종료한다.
6. 배포 폴더 전체를 전달한다. 실행 파일 하나만 복사해서는 실행할 수 없다.

GitHub Actions 설정은 저장소에 추가되어 있으며, 실제 원격 실행은 커밋/푸시 후 확인한다.
GitLab 설정에는 `windows` 태그와 Python 3.14가 설치된 Runner가 필요하다.
자동 검증 파일의 추가를 원격 검증 통과로 해석하지 않는다.

## 실제 기관 자료에서 확인할 것

자료 반입이 허용된 PC에서 담당자가 표본을 선정하고, 본문·개인정보를 저장소에 커밋하지 않는다.

| 시나리오 | 평가 방법 |
|---|---|
| 첫날 업무 파악 | 후임자가 자료만으로 주요 업무를 찾는 데 걸리는 시간과 누락 업무를 기록 |
| 이번 달 할 일 | 전임자가 확인한 실제 업무 주기와 앱의 일정 제안을 대조 |
| 지난 처리 순서 | 단계의 순서·누락·추정 표시와 각 근거 문서를 검수 |
| 질문과 출처 | 답해야 할 질문과 유보할 질문을 분리해 정답·근거 문서·필수 숫자를 기록 |
| 자료 변경 | 수정·삭제·복원·공유 폴더 단절 이후 결과와 사용자 교정 보존을 확인 |
| 저사양 PC | 8GB 장비에서 첫 질문/후속 질문의 지연·최대 메모리·취소 시간을 측정 |

첫 평가셋은 100문항 이상을 권장하며, 조정용과 최종 검증용을 분리한다. 3회 이상 반복해
응답/유보 정확도, 출처 적합성, 첫 질문 지연, p50/p95 지연을 기록한다. 합격선은 기관 담당자와
제품 기준서 §10을 기준으로 정한다. 합성 9문항의 과거 통과 수치를 실제 기관 정확도로 대체하지 않는다.

## HWP 회귀 표본

현재 세션에는 HWP 생성 도구가 연결되어 있지 않다. 실제 한글에서 만든 비식별 표본이나
재배포가 허용된 공개 표본으로 본문·표·압축·암호·구버전 실패 동작을 검증한다.
단일 HWP 성공 사례만으로 형식 전반의 지원을 선언하지 않는다.
기존 `NUNCHICOACH_SAMPLES`와 `app.tools.parse_bench`를 사용하면 본문 대신 해시와 추출량으로 회귀를 추적할 수 있다.

## 배포 전 남은 결정

- 공개 라이선스: 소유자가 허용할 사용·재배포 조건을 결정한다. 임의로 라이선스를 부여하지 않는다.
- 기관 도입: 승인 모델, 모델 재배포 조건, 데이터 저장·백업 정책, 실행 파일 서명 및 반입 절차를 확정한다.
- 실제 오프라인 PC: Python 없는 PC에서 실행 파일 폴더를 복사해 실행한다. 모델 설치는 별도로 확인한다.
- 기존 프로젝트: 최초 업그레이드 시 파서/색인을 다시 준비하므로 처리 시간을 확보한다. 사용자 교정은 보존한다.

위 항목은 자동 테스트만으로 완료할 수 없는 검증 또는 소유자 결정이다.
