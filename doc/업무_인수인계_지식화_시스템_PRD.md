## 1. 문서 목적

이 문서는 전임자 PC, 공유 폴더, USB, 백업 디스크 등에 흩어진 업무 자료를 안전하게 조사하고, 검색 가능한 지식으로 전환하여 신임 담당자의 업무 인수 시간을 줄이는 독립 실행형 소프트웨어의 최종 제품 요구사항을 정의한다.

본 문서는 다음 사항의 단일 기준선이다.

- 제품의 목표와 비목표
- 사용자와 핵심 사용 시나리오
- 출시 단계별 기능 범위와 우선순위
- 기능·비기능 요구사항과 합격 기준
- 로컬 AI, 검색, 문서 파싱 및 보안 설계 원칙
- 데이터 구조와 사용자 화면
- 시험, 출시 및 운영 기준

기존 기획서와 설계 보고서 사이의 기술·범위 차이는 본 문서의 결정으로 대체한다.

## 2. 제품 한 줄 정의

> 전임자의 파일을 단순히 재배치하는 프로그램이 아니라, 원본을 보존하면서 업무의 구조·일정·핵심 문서·과거 처리 근거를 찾아 다음 담당자가 검증 가능한 지식으로 활용하게 하는 로컬 AI 기반 업무 인수인계 시스템.

## 3. 배경과 문제

순환보직이 일반적인 공공기관에서는 담당자가 2~3년 주기로 새로운 업무를 맡는다. 인수 자료는 개인 PC와 공유 폴더에 누적되지만, 파일명과 폴더 구조가 작성자 개인 습관에 따라 달라 다음과 같은 문제가 반복된다.

- `최종`, `최종2`, `진짜최종` 등 버전 관계를 알기 어렵다.
- 연도·확장자·임시 폴더 위주로 저장되어 실제 업무 구조가 드러나지 않는다.
- HWP, HWPX, DOCX, XLSX, PPTX, PDF, 이미지, 이메일 등 형식이 혼재한다.
- 문서를 하나씩 열어보지 않으면 내용을 파악하기 어렵다.
- 업무의 연간 일정, 반복 절차, 핵심 자료와 과거 판단 근거가 문서 사이에 흩어져 있다.
- 개인정보와 기밀정보 때문에 외부 클라우드 AI를 사용할 수 없는 경우가 많다.
- 자동 이동·삭제·이름 변경은 자료 유실과 감사 위험을 만든다.

현재 사용자는 파일 탐색기, 개별 문서 프로그램, 수동 폴더 정리 및 전임자의 구두 설명에 의존한다. 이 과정은 시간이 오래 걸리고 담당자 교체 때마다 반복된다.

## 4. 제품 목표

### 4.1 핵심 목표

1. 원본을 변경하지 않고 대량의 업무 자료를 조사·색인한다.
2. HWP를 포함한 주요 문서의 본문과 표를 가능한 범위에서 추출한다.
3. 파일명, 본문, 날짜, 업무, 작성자 및 태그로 빠르게 검색한다.
4. 완전 중복과 버전 후보를 안전하게 식별한다.
5. 로컬 LLM을 이용해 문서를 요약·분류하되 결과를 사용자가 검증하게 한다.
6. 자연어 질문에 근거 문서와 정확한 원문 위치를 포함해 답한다.
7. 전임자의 실제 업무 범주, 반복 시기, 대표 문서와 권장 학습 순서를 제시한다.
8. 근거가 연결된 인수인계 보고서 초안을 생성한다.
9. 인터넷 없이 설치·실행·백업·복구할 수 있게 한다.

### 4.2 사용자 성과 목표

- 첫 실행 후 파일 목록과 기본 검색 결과를 빠르게 확인할 수 있다.
- 신임 담당자는 수천 개의 파일 중 먼저 읽을 문서를 식별할 수 있다.
- 업무별 과거 자료와 전년도 처리 흐름에 직접 접근할 수 있다.
- AI 답변의 근거를 원문에서 즉시 검증할 수 있다.
- 전임자는 원본 손상 우려 없이 정리된 복사본과 인수인계 초안을 만들 수 있다.

### 4.3 사업 성과 지표

실제 도입 전 비식별 시험군과 사용자 연구를 통해 기준값을 확정하며, 출시 후 다음을 측정한다.

| 지표 | 정의 | 목표 방향 |
|---|---|---|
| 첫 유용 결과 도달 시간 | 프로젝트 생성부터 검색 가능한 파일 목록 표시까지의 시간 | 단축 |
| 핵심 문서 탐색 시간 | 주어진 업무 질문의 근거 문서를 찾는 데 걸린 시간 | 기존 대비 60% 이상 단축 |
| 검색 성공률 | 사용자가 5분 안에 올바른 근거 문서를 찾은 과제 비율 | 85% 이상 |
| AI 근거 확인률 | AI 답변에서 사용자가 출처를 열어 확인한 비율 | 측정 및 지속 개선 |
| 사용자 교정률 | 전체 AI 분류 중 사람이 수정한 비율 | 파일럿 후 감소 추세 |
| 원본 훼손 사고 | 애플리케이션이 원본을 변경·삭제한 사고 | 0건 |
| 재사용률 | 설치 후 30일 내 다시 사용한 파일럿 사용자 비율 | 70% 이상 |

## 5. 비목표

다음은 초기 제품의 목표가 아니다.

- 전자문서 결재 또는 기록관리시스템을 대체하지 않는다.
- 법적 효력이 있는 기록물 분류·폐기 결정을 자동화하지 않는다.
- AI가 문서의 사실성, 적법성 또는 최종본 여부를 확정하지 않는다.
- 원본 파일을 자동 이동·삭제·덮어쓰기·이름 변경하지 않는다.
- 클라우드 AI 또는 외부 분석 서버를 사용하지 않는다.
- 여러 기관이 동시에 사용하는 중앙형 협업 시스템을 초기 버전에 포함하지 않는다.
- 모든 HWP 문서의 레이아웃을 완벽하게 재현하거나 편집하지 않는다.
- AI가 생성한 인수인계서를 사람의 검토 없이 공식 문서로 확정하지 않는다.

## 6. 대상 사용자

### 6.1 주 사용자: 신임 담당자

- 새로운 보직의 자료와 업무 흐름을 빠르게 파악해야 한다.
- 파일 위치나 정확한 문서명을 모르는 상태에서 질문한다.
- 먼저 읽어야 할 자료와 반복 일정을 알고 싶어 한다.
- AI 답변을 신뢰하기 전에 원문을 확인할 수 있어야 한다.

### 6.2 보조 사용자: 전임 담당자

- 이임 전에 자료를 안전하게 정리하고 설명서를 남기고 싶어 한다.
- 중복과 버전 후보를 확인하고 대표 문서를 지정한다.
- 자동 생성된 인수인계서 초안을 검수·보완한다.

### 6.3 관리자: 팀장·과장

- 부서 자료의 업무 분포와 핵심 문서 누락 여부를 확인한다.
- 인수인계 품질과 검토 상태를 확인한다.
- 공식 보고서로 내보내기 전에 내용을 승인한다.

### 6.4 IT·보안 관리자

- 오프라인 설치 패키지와 모델 파일을 검증·배포한다.
- 허용 경로, 제외 규칙, 데이터 보존 및 내보내기 정책을 설정한다.
- 감사 로그와 오류 보고서를 검토한다.

## 7. 설계 결정

| 영역 | 최종 결정 | 이유 |
|---|---|---|
| 실행 방식 | Windows 독립 실행형 로컬 애플리케이션 | 망분리·폐쇄망과 사용자 PC 자료 접근에 적합 |
| UI | Python + PySide6 | 문서 처리 계층과 단일 언어로 구성하여 패키징·운영 복잡도 축소 |
| 애플리케이션 구조 | UI와 서비스 계층을 분리하되 MVP에서는 단일 설치 패키지 | 향후 API 분리가 가능하면서 초기 운영 부담 최소화 |
| 백그라운드 처리 | 별도 작업 프로세스와 영속 작업 큐 | UI 멈춤 방지, 중단 재개 및 오류 격리 |
| 메타데이터 DB | SQLite | 단일 PC 배포, 백업, 이동 및 유지보수 용이 |
| 키워드 검색 | SQLite FTS5 | 별도 서버 없이 본문·파일명 통합 검색 가능 |
| 벡터 검색 | 교체 가능한 어댑터, 기본 후보 sqlite-vec | 메타데이터와 벡터의 단일 저장을 우선하되 벤치마크 후 확정 |
| 로컬 LLM | Ollama, 기본 모델은 검증된 소형 모델 프로필로 제공 | 모델 교체 가능성과 완전 로컬 실행 확보 |
| OCR | 엔진 어댑터 구조, 한국어 표본 평가 후 기본 엔진 확정 | Tesseract/PaddleOCR 등 엔진 교체 가능 |
| 정리 방식 | 사용자 지정 위치에 복사본 생성만 지원 | 원본 훼손 위험 제거 |
| 보고서 출력 | Markdown, DOCX, PDF | 안정적인 자동 생성 우선 |
| HWP 출력 | 후속 기능, 별도 기술·라이선스 검증 후 제공 | 한컴 설치·자동화·변환 품질 의존성 분리 |
| AI 장애 시 동작 | 스캔·파싱·중복·키워드 검색은 계속 사용 가능 | AI를 기본 기능의 단일 장애점으로 만들지 않음 |

FastAPI는 다중 프로세스 통신이나 향후 조직형 배포가 필요할 때 도입할 수 있으나 MVP 필수 구성요소로 두지 않는다.

## 8. 출시 범위와 우선순위

우선순위는 다음과 같이 정의한다.

- **P0:** 최초 운영 가능한 제품에 반드시 포함
- **P1:** AI 기반 업무 이해 버전에 포함
- **P2:** 고도화 버전에 포함
- **제외:** 별도 제품 또는 후속 검토

### 8.1 릴리스 구성

| 릴리스 | 제품 목표 | 핵심 범위 |
|---|---|---|
| Phase 0 | 기술 타당성 입증 | 대표 문서군, HWP·표 파싱, OCR, 하드웨어, 오프라인 설치 벤치마크 |
| MVP 1 | 안전한 문서 조사와 검색 | 스캔, 메타데이터, 파싱, 해시 중복, FTS 검색, 진행률, 재개, 감사 로그 |
| MVP 2 | 문서 이해와 검토 | 로컬 LLM 요약·분류·키워드, 사용자 교정, 버전 후보, 대표 문서 |
| MVP 3 | 근거 기반 업무 검색 | 하이브리드 검색, RAG, 출처 위치, 업무 자동 발견, 타임라인 |

| 후속 | 조직 지식화 | 문서 관계망 고도화, 부서 다중 사용자, 중앙 정책, HWP 출력 |

## 9. 핵심 사용자 시나리오

### 시나리오 A: 전임자 자료 처음 조사하기

1. 사용자가 새 프로젝트를 만든다.
2. 로컬 폴더, USB 또는 UNC 공유 경로를 추가한다.
3. 시스템이 읽기 권한과 예상 파일 수·용량을 점검한다.
4. 사용자가 제외 규칙과 저장 위치를 확인한다.
5. 시스템이 메타데이터를 먼저 수집해 파일 목록을 빠르게 표시한다.
6. 본문 추출, 해시, AI 분석은 백그라운드 단계로 진행한다.
7. 사용자는 완료를 기다리지 않고 이미 처리된 자료를 검색한다.

### 시나리오 B: 특정 업무의 핵심 자료 찾기

1. 사용자가 `작년 행정사무감사 수질 자료`를 검색한다.
2. 시스템이 파일명·본문·업무 분류·의미 유사도를 결합해 결과를 제시한다.
3. 사용자는 날짜, 문서 유형, 작성자와 분석 상태로 필터링한다.
4. 문서를 선택하면 요약, 버전 후보, 원문 위치와 관련 문서를 확인한다.

### 시나리오 C: 자료에 질문하기

1. 사용자가 `작년에 이 업무를 어떤 순서로 처리했어?`라고 질문한다.
2. 시스템이 관련 문서 조각을 검색하고 답변 가능성을 판단한다.
3. 근거가 충분하면 단계별 답변과 문서·페이지·시트 출처를 표시한다.
4. 근거가 부족하면 추정하지 않고 확인 가능한 자료가 부족하다고 안내한다.
5. 사용자는 출처를 열어 원문을 확인한다.

### 시나리오 D: AI 결과 검수하기

1. 사용자가 낮은 신뢰도 또는 미분류 목록을 연다.
2. AI가 제안한 업무, 유형, 연도, 제목과 근거 구절을 확인한다.
3. 사용자가 값을 수정하거나 새 업무 범주를 지정한다.
4. 시스템은 교정 이력과 적용 범위를 저장한다.
5. 승인된 교정은 이후 유사 문서 분류의 참고 예시로 사용한다.

### 시나리오 E: 인수인계 보고서 만들기

1. 사용자가 포함할 업무, 기간과 템플릿을 선택한다.
2. 시스템이 업무 개요, 반복 일정, 주요 현안, 핵심 문서와 권장 학습 순서를 작성한다.
3. 모든 사실성 문장에 근거 문서를 연결한다.
4. 근거가 없는 제안이나 추론은 별도로 표시한다.
5. 사용자가 섹션별로 수정·승인한다.
6. Markdown, DOCX 또는 PDF로 내보낸다.

| SEC-005 | P0 | 로그에 원문 본문이나 민감정보를 기본 기록하지 않는다. | 로그 검사에서 본문과 탐지된 개인정보 패턴이 노출되지 않는다. |
| SEC-006 | P0 | 분석, 교정, 복사, 보고서 생성·내보내기를 감사 로그에 남긴다. | 작업자, 시각, 대상, 결과, 버전을 확인할 수 있다. |
| SEC-007 | P1 | 주민등록번호, 전화번호, 계좌번호 등 정책 기반 민감정보 후보를 탐지한다. | 탐지 규칙은 버전 관리되고 결과는 경고·인덱싱 제외에 사용된다. |
| SEC-008 | P1 | 관리자는 민감정보 인덱싱과 AI 분석 제외 규칙을 설정한다. | 제외된 내용은 chunk·embedding·프롬프트에 포함되지 않는다. |
| SEC-009 | P0 | 설치 패키지와 모델에 서명·해시·라이선스 목록을 포함한다. | 오프라인 검증 절차로 위변조 여부를 확인할 수 있다. |
| SEC-010 | P1 | 프로젝트 보존기간 만료와 안전한 삭제를 지원한다. | DB, 벡터, 캐시, 미리보기, 백업 범위를 사용자에게 표시하고 삭제한다. |

## 14. 분류·추천 설계

### 14.1 업무 분류

업무 분류는 통제된 분류 체계와 자동 발견을 결합한다.

1. 기관 또는 사용자가 기본 업무 체계를 정의한다.
2. 규칙 기반 신호와 AI가 기존 업무 중 후보를 제시한다.
3. 맞는 범주가 없으면 `신규 업무 후보`로 보낸다.
4. 사용자가 승인해야 공식 업무 범주가 된다.
5. 승인된 교정은 동일 프로젝트의 후속 분석 예시로 사용할 수 있다.

AI가 자유로운 이름을 매번 생성해 업무 분류가 분산되는 것을 허용하지 않는다.

### 14.2 핵심 문서 추천 점수

추천 점수는 다음 신호의 가중 합으로 계산하고 구성 요소를 표시한다.

- 최근성
- 반복 업무에서의 사용 빈도
- 문서 유형 가중치
- 사용자가 지정한 대표 문서 여부
- 다른 문서와의 연결도
- 최종·송부·결재본 후보 근거
- 검색·열람 빈도
- AI 중요도 제안

AI 단일 점수만으로 추천 순위를 결정하지 않는다.

### 14.3 AI 결과 신뢰 수준

UI에는 보정되지 않은 숫자 확률 대신 다음 상태를 사용한다.

| 상태 | 의미 | 기본 행동 |
|---|---|---|
| 높음 | 규칙·검색·모델 결과가 일치하고 검증 자료에서 안정적 | 일반 목록에 표시 |
| 보통 | 근거가 있으나 후보가 경합 | 확인 권장 |
| 낮음 | 근거 부족, 모델 불일치 또는 추출 품질 저하 | 검토함으로 이동 |
| 판정 불가 | 본문 부족·파싱 실패·지원 불가 | 수동 태깅 또는 원본 열기 |

신뢰 수준 산식은 검증 세트 결과로 보정하며 모델이 스스로 반환한 confidence 값만 사용하지 않는다.

## 15. 검색 및 RAG 설계

### 15.1 검색 단계

1. 질문에서 기간, 업무, 문서 유형과 명시 키워드를 추출한다.
2. SQLite FTS5로 파일명·본문·태그를 검색한다.
3. 벡터 검색으로 의미상 관련 chunk를 찾는다.
4. 메타데이터 필터와 접근 정책을 적용한다.
5. 중복 chunk를 제거하고 문서·버전 다양성을 확보한다.
6. 재순위화하여 답변 컨텍스트를 구성한다.
7. 생성 모델이 출처 식별자를 유지한 답변을 생성한다.
8. 후처리기가 모든 인용과 문장 근거를 검증한다.

### 15.2 출처 단위

| 형식 | 최소 출처 위치 |
|---|---|
| HWP/HWPX/DOCX | 문단·표 식별자, 가능한 경우 쪽 번호 |
| PDF | 페이지 번호와 텍스트 영역 |
| XLS/XLSX/CSV | 시트명과 셀 범위 |
| PPT/PPTX | 슬라이드 번호와 객체 |
| 이미지/OCR | 페이지 또는 이미지와 영역 |
| TXT/EML | 줄 또는 섹션 범위 |

### 15.3 답변 정책

- 답변은 검색된 프로젝트 자료만 근거로 작성한다.
- 일반 지식으로 빈 부분을 채우지 않는다.
- 자료에 없는 순서·원인·담당자를 단정하지 않는다.
- 자료가 충돌하면 양쪽 근거를 제시한다.
- 추정이 필요한 경우 `추정`으로 명시하고 사용 근거를 보여준다.
- 민감정보 정책상 제외된 문장은 답변 컨텍스트에 포함하지 않는다.

## 16. 프롬프트 및 모델 관리

- 프롬프트는 코드에 직접 흩어두지 않고 버전 있는 템플릿으로 관리한다.
- 각 작업은 요약, 분류, 키워드, 질의응답처럼 단일 목적을 가진다.
- 모든 구조화 응답은 JSON Schema로 검증한다.
- 스키마 실패 시 제한된 횟수만 재시도하고 원문 응답을 진단용으로 격리한다.
- 모델 프로필은 컨텍스트 길이, 양자화, 메모리 요구량, 라이선스, 해시와 검증 결과를 포함한다.
- 생성 모델과 임베딩 모델을 분리한다.
- 모델을 바꿔도 기존 사용자 교정은 유지한다.
- 새 모델은 비식별 고정 검증 세트를 통과해야 기본 모델로 승격한다.
- 프롬프트 입력에는 최소한의 필요한 chunk만 포함한다.

## 17. 보안 및 개인정보 설계

### 17.1 보안 원칙

1. Local-first와 기본 네트워크 차단
2. 최소 권한과 자료원 읽기 전용
3. 원본과 파생 데이터의 동일 수준 보호
4. 사용자 승인 없는 외부 반출 금지
5. 모든 변경·생성·내보내기의 추적 가능성
6. 검증된 오프라인 공급망

### 17.2 보호 대상

- 원본 경로와 파일 메타데이터
- 추출 본문과 OCR 결과
- 임베딩과 검색 인덱스
- AI 요약·질문·답변
- 사용자 교정과 업무 분류
- 보고서와 정리된 복사본
- 오류·감사 로그와 백업

### 17.3 통제

- 프로젝트 폴더에 Windows ACL을 적용한다.
- 저장 데이터 암호화 키는 OS 사용자 보호 저장소로 관리한다.
- Ollama는 승인된 로컬 주소로만 통신하고 외부 바인딩을 금지한다.
- 로그는 원문을 포함하지 않고 파일 식별자와 오류 코드 중심으로 기록한다.
- 민감정보 탐지 결과는 경고, 검색 제외, AI 제외, 보고서 마스킹 정책과 연동한다.
- 설치 파일, 모델, OCR 언어팩, Python 라이브러리의 해시와 라이선스 목록을 제공한다.
- 관리자용 오프라인 업데이트는 서명과 롤백 절차를 포함한다.
- 내보내기 시 대상 경로와 포함 문서·민감정보 경고를 다시 확인한다.

## 18. 비기능 요구사항

### 18.1 안전성과 신뢰성

| ID | 요구사항 |
|---|---|
| NFR-SAF-001 | 정상·오류·취소·강제 종료 상황에서 원본을 변경하지 않는다. |
| NFR-SAF-002 | 복사 정리 결과는 원본과 해시가 일치해야 성공 처리한다. |
| NFR-SAF-003 | 앱 충돌 또는 전원 중단 후 DB 일관성을 검사하고 작업을 재개한다. |
| NFR-SAF-004 | 사용자 교정과 승인 결과는 자동 재분석으로 덮어쓰지 않는다. |
| NFR-SAF-005 | 위험 작업은 대상·영향·복구 가능성을 미리 보여준다. |

### 18.2 성능

기준 하드웨어와 시험 자료군은 Phase 0에서 고정한다. MVP 1의 잠정 기준은 다음과 같다.

| 항목 | 잠정 목표 |
|---|---|
| 파일 목록 첫 표시 | 스캔 시작 후 5초 이내에 점진 표시 |
| 메타데이터 조사 | 로컬 SSD의 일반 업무 파일 10,000건을 15분 이내 조사 |
| 목록·필터 반응 | 10만 건 프로젝트에서 사용자 동작의 p95 500ms 이하 |
| 키워드 검색 | 10만 건 프로젝트에서 p95 2초 이하 |
| 일시정지·취소 반응 | 요청 후 5초 이내 안전 지점에서 반응 |
| 앱 유휴 메모리 | 500MB 이하 목표 |
| AI 분석 | 기준 PC·문서군별 처리량과 예상 완료 시간을 UI에 표시 |

대용량 파일과 네트워크 공유 경로는 별도 성능 등급으로 측정한다. 파일 총용량과 디스크 속도를 무시한 단일 처리시간 약속은 하지 않는다.

### 18.3 품질

| 항목 | 출시 게이트 |
|---|---|
| 원본 비변경 | 자동·수동 시험 전 항목 통과, 사고 0건 |
| 메타데이터 수집 | 읽을 수 있는 검증 파일의 99.9% 이상 목록화 |
| 완전 중복 | SHA-256 기준 정밀도 100% |
| 본문 추출 | 지원·비암호화 표본의 95% 이상에서 핵심 본문 추출 성공 |
| 구조 출처 | 추출 성공 chunk의 99% 이상에 원문 위치 존재 |
| 업무 분류 | 승인된 검증 세트에서 macro F1 0.80 이상을 기본 목표로 설정 |
| 버전 후보 | 검증 후보군 정밀도 0.90 이상, 자동 확정 0건 |
| RAG 출처 | 평가 대상 사실 문장의 95% 이상이 유효 출처를 가짐 |
| 근거 없는 단정 | 고정 평가 세트에서 5% 미만, 중대 오류 0건 |
| 복구 | 강제 종료·재시작 시험에서 작업 중복·DB 손상 없이 재개 |

실제 수치는 Phase 0 기준선 결과가 지나치게 다를 경우 제품 책임자와 품질 책임자의 승인으로 조정하되, 변경 사유와 사용자 영향을 기록한다.

### 18.4 호환성과 접근성

- Windows 10/11 64-bit에서 설치·실행한다.
- 한글, 영문, 숫자와 Windows 허용 특수문자 경로를 지원한다.
- 장치 분리, UNC 재연결과 긴 경로를 안전하게 처리한다.
- 기본 확대·축소, 키보드 이동, 명확한 포커스와 고대비 테마를 지원한다.
- 색상만으로 분석 상태나 경고를 구분하지 않는다.
- 오류 메시지는 기술 코드와 사용자가 취할 조치를 함께 제공한다.

### 18.5 유지보수성

- 파서, OCR, 임베딩, 생성 모델과 벡터 저장소를 어댑터로 분리한다.
- DB 스키마 마이그레이션과 롤백 가능성을 시험한다.
- 진단 보고서는 원문 없이 환경·버전·오류 통계를 내보낸다.
- 재현 가능한 오프라인 빌드와 의존성 잠금 파일을 유지한다.

## 19. 오류 처리 원칙

| 오류 유형 | 사용자 처리 |
|---|---|
| 접근 권한 없음 | 경로와 필요한 권한을 안내하고 다른 파일 처리는 계속 |
| 파일 잠김 | 재시도 대기열에 넣고 건너뛰기 가능 |
| 암호 문서 | 암호 해제를 시도하지 않고 수동 태깅·원본 열기 제공 |
| 파서 실패 | 형식·파서 버전·오류 코드를 기록하고 메타데이터 검색은 유지 |
| OCR 실패 | 원본 이미지 미리보기와 수동 설명 입력 제공 |
| Ollama 중단 | AI 작업만 일시정지하고 기본 기능 유지 |
| 모델 응답 오류 | 제한 재시도 후 검토함에 원인 표시 |
| 공유 경로 단절 | 작업을 대기 상태로 전환하고 재연결 후 재개 |
| 저장 공간 부족 | 새 파생 데이터 생성을 중단하고 필요한 예상 공간 안내 |
| DB 무결성 오류 | 읽기 전용 복구 모드와 백업 복원 안내 |

오류 메시지는 원인, 영향 범위, 자동 복구 여부, 사용자가 할 수 있는 행동을 포함한다.

## 21. 시험 전략

### 21.1 Phase 0 기준 자료군

기관 승인을 받은 비식별 자료로 최소 다음 표본을 구성한다.

| 형식 | 최소 표본 | 필수 변형 |
|---|---:|---|
| HWP | 100 | 표, 글상자, 암호, 구버전, 손상 파일 |
| HWPX | 100 | 표, 이미지, 각주, 다양한 생성 버전 |
| PDF | 100 | 텍스트, 스캔, 혼합, 회전, 암호 |
| XLS/XLSX | 100 | 다중 시트, 병합 셀, 수식, 숨김 시트 |
| DOCX | 50 | 표, 머리글, 각주, 포함 객체 |
| PPT/PPTX | 50 | 도형, 표, 노트, 이미지 텍스트 |
| 이미지 | 50 | 스캔 품질, 기울기, 저해상도, 한글 표 |
| 오류·보안 | 50 | 접근 거부, 잠금, 비정상 크기, 위장 확장자 |

### 21.2 시험 종류

- 단위 시험: 메타데이터, 해시, 날짜, 경로, 분류 규칙
- 계약 시험: 각 파서·OCR·LLM 어댑터 입출력
- 통합 시험: 스캔부터 검색·보고서까지 전체 파이프라인
- 회귀 시험: 고정 문서군의 추출·검색·AI 품질 비교
- 중단 복구 시험: 강제 종료, 장치 분리, 네트워크 단절, 디스크 부족
- 보안 시험: 외부 통신, ACL, 로그 노출, 경로 조작, 비정상 문서
- 성능 시험: 1만·10만 파일, 로컬 SSD·USB·UNC, CPU·GPU 프로필
- 사용성 시험: 신임자·전임자·관리자의 실제 업무 과제
- 내보내기 시험: DOCX·PDF·Markdown의 한글, 표, 출처와 페이지 구성

### 21.3 AI 평가 세트

전문가가 정답을 부여한 문서와 질문을 별도로 관리한다.

- 업무·문서 유형 분류
- 제목·연도·키워드 추출
- 요약의 핵심 사실 보존
- 버전 후보와 대표 문서
- 검색 관련성
- 답변 정확성, 근거 충실성, 인용 위치
- 답변을 유보해야 하는 질문
- 상충 문서를 찾아야 하는 질문

평가 세트는 모델 프롬프트 작성 자료와 분리하여 과적합을 방지한다.

## 22. 릴리스 승인 기준

### 22.1 MVP 1

- 모든 P0 요구사항이 승인된 시험에서 통과한다.
- 원본 변경 시험에서 변경·삭제·이름 변경이 0건이다.
- HWP/HWPX/PDF/XLSX 핵심 파싱 기준을 충족한다.
- 10만 건 자료에서 검색·필터 성능 기준을 충족한다.
- 앱 강제 종료와 UNC 단절 후 작업을 재개할 수 있다.
- 외부 인터넷이 차단된 PC에서 설치와 전체 P0 흐름이 동작한다.
- 보안·라이선스·오프라인 설치 검토가 완료된다.

### 22.2 MVP 2·3

- AI가 없어도 MVP 1 기능에 회귀가 없다.
- 분류·요약·RAG 평가 기준을 충족한다.
- 모든 AI 결과에 모델·프롬프트·근거·상태가 추적된다.
- 근거 부족 답변 유보와 상충 자료 표시가 검증된다.
- 민감정보 제외 정책이 chunk, embedding, 프롬프트와 내보내기에 적용된다.

### 22.3 v1.0

- 실제 신임자·전임자 파일럿에서 핵심 문서 탐색 시간이 기준 대비 60% 이상 단축된다.
- 인수인계 보고서의 모든 사실성 섹션에 출처 또는 사용자 입력 표시가 있다.
- 복사 정리 시험에서 원본 변경 0건, 복사 성공 파일 해시 일치 100%를 달성한다.
- 백업·복원·보존기간 만료 절차가 운영 문서와 함께 검증된다.

## 25. 후속 범위

다음 기능은 v1.0 이후 별도 요구사항 검토를 거친다.

- 부서 단위 공용 저장소와 다중 사용자 동시 접근
- 기관별 중앙 분류 체계와 정책 배포
- 역할 기반 세부 권한과 승인 워크플로
- 문서 관계망 시각화 고도화
- 기록관리시스템·전자결재 연계
- 이메일 PST/MSG와 첨부 관계 분석 고도화
- 한컴오피스 자동화를 통한 HWP/HWPX 출력
- 부서 간 인수인계 이력과 장기 지식 축적
- 기관 내부 전용 모델 튜닝

조직형 버전에서는 SQLite 파일을 공유 폴더에 직접 놓아 동시 사용하는 방식을 채택하지 않는다. 중앙 서비스와 조직용 DB를 별도 설계한다.

## 26. 용어

| 용어 | 정의 |
|---|---|
| 원본 | 사용자가 등록한 자료원에 존재하며 애플리케이션이 수정하지 않는 파일 |
| 파생 데이터 | 추출 본문, OCR, chunk, embedding, AI 분석, 미리보기와 보고서 |
| 완전 중복 | SHA-256이 동일한 파일 |
| 버전 후보 | 이름·본문·날짜가 유사해 같은 문서 계보일 가능성이 있는 파일군 |
| 대표 문서 | 업무 이해를 위해 사용자가 먼저 확인하도록 추천 또는 지정된 문서 |
| 업무 분류 | 예산, 감사, 계약 등 실제 담당 업무 의미를 나타내는 통제 범주 |
| chunk | 검색과 AI 분석을 위해 원문 위치를 유지한 작은 문서 단위 |
| 근거 | 답변이나 보고서 문장을 뒷받침하는 문서와 원문 위치 |
| RAG | 검색된 프로젝트 자료를 근거로 생성 모델이 답하는 구조 |
| 검토함 | 낮은 신뢰도, 충돌, 오류, 민감정보와 미분류 항목을 사람이 확인하는 화면 |

## 27. 최종 제품 원칙

1. **원본은 항상 보존한다.**
2. **AI가 없어도 조사와 검색은 동작한다.**
3. **파싱 품질이 AI 기능보다 우선한다.**
4. **AI의 판단은 제안이며 사람의 교정이 최종이다.**
5. **모든 중요한 AI 답변과 보고서 문장은 근거로 돌아갈 수 있어야 한다.**
6. **분류는 파일 형식이 아니라 실제 업무 의미를 중심으로 한다.**
7. **완전 오프라인 설치·실행·업데이트·복구가 가능해야 한다.**
8. **기능 수보다 신뢰성, 재현성, 검증 가능성을 우선한다.**

이 원칙 중 하나라도 충족하지 못하는 기능은 출시 범위를 줄이거나 후속 단계로 이동한다.

## 28. 기존 요구사항 추적표

| 기존 요구사항 | 본 PRD 반영 위치 | 처리 결과 |
|---|---|---|
| R1 지정 폴더 재귀 스캔 | PRJ-002~005, ING-001~008 | P0 확정 |
| R2 파일 메타데이터 저장 | ING-002~005, 데이터 모델 | P0 확정, 날짜 출처 분리 강화 |
| R3 주요 문서 포맷 파싱 | PAR-001~008 | 핵심 포맷 P0, 이미지 OCR P1 |
| R4 로컬 LLM 요약·분류 | AIA-001~008 | P1로 분리하여 기본 기능과 독립 |
| R5 유사·중복·최신본 추정 | DUP-001~005 | 완전 중복 P0, 버전 후보 P1, 자동 확정 금지 |
| R6 검색·자연어 질의 | SRH-001~006, RAG-001~006 | 키워드 검색 P0, RAG P1 |
| R7 사람의 검수·수정 UI | 검토함, AIA-005~008 | P1 확정 |
| R8 인수인계서 자동 초안 | RPT-001~006 | P2·v1.0 범위 |
| R9 민감정보 탐지 | SEC-004~008 | P1, 저장·인덱싱·프롬프트 통제까지 확대 |
| R10 완전 오프라인 | SEC-001~002, SEC-009 | P0/P1 출시 게이트 |
| R11 분류 규칙 커스터마이징 | PRJ-003, KNW-001, 분류 설계 | 단계별 반영 |
| R12 부서 단위 이력 축적 | 후속 범위 | 조직형 아키텍처로 별도 설계 |

이 추적표를 기준으로 기존 문서의 요구사항이 누락되거나 본 PRD와 다르게 해석되는 것을 방지한다.
