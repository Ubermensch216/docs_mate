# 단계별 보완 계획

## 근거

사용자가 제공한 클로드 분석과 2026-09-15 저장소 분석을 대조한다. 과거 전체 테스트/실제 AI/성능 수치는 참고 기록으로 취급하고 새 변경은 다시 검증한다.

## 단계

1. **UI/UX 우선** — 별도 `UI_UX_개선계획_2026-09-15.md`에 따라 문서 페이지 탐색, 명확한 빈 상태, 모델 설정, 비동기 상태 확인, 질문 대기·취소를 먼저 구현한다.
2. **데이터·AI 신뢰성** — 수정된 파일의 파생 데이터 갱신, 원본 복귀와 접근 실패 상태, 로컬 프록시 차단, 숫자 검증, 모델 태그와 작업 수명을 보완한다.
3. **배포·진단·개발 흐름** — 로고 포함, 잠금 파일 및 오프라인 설치 경로, 민감 내용 없는 진단 로그, 자동 테스트 설정, 기준 문서 갱신, 배포본 재빌드와 자체 점검을 수행한다.
4. **종합 검증과 인계** — 회귀 테스트·렌더링 결과를 기록하고 완료 항목과 실제 환경 검증이 필요한 항목을 구분한다.

## 별도 조건이 필요한 항목

- 실제 기관 문서 품질과 8GB PC 성능은 해당 자료·장비로 검증해야 한다. 합성 결과로 대체하지 않는다.
- 실제 HWP 파일 회귀 표본은 유효한 공개/합성 문서의 생성 경로와 재배포 권한을 확인한 후 추가한다.
- 프로젝트의 공개 라이선스는 소유자의 배포 의사가 필요하므로 임의로 부여하지 않는다.
- 실제 AI 테스트는 모델 설치가 없는 일반 테스트 환경에서 강제하지 않는다. 별도 실행 경로와 사전 조건을 명확히 한다.
- 성능은 첨부 분석에서 현재 규모에 문제가 없었던 영역을 우선 재작성하지 않는다.

## 검증 원칙

테스트 임시 산출물은 저장소 내 `.test_runs`에 둔다. 실제 사용자 프로젝트와 원본을 변경하지 않고 합성 자료로 검사한다. 의미 있는 동작 변경에 회귀 테스트를 추가하고 마지막에 전체 테스트를 실행한다.

## 진행 결과

1단계 UI/UX를 먼저 구현한 뒤 2단계 데이터·AI 신뢰성과 3단계 배포·진단 보완을 완료했다. 검증용 Windows 실행 파일을 새 경로에 빌드하고 합성 문서 77개 자체 점검 및 실제 모델 검사 36개를 통과했다. 4단계의 최종 수치와 인계 자료는 [보완 작업 결과 보고](보완작업_결과보고_2026-09-15.md)에 기록한다.
